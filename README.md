# MeetSync

6인 이상 도메인 기반 일정 조율 웹앱 — **관계 비용을 시스템으로 이관하는 조율 도구**.

[meetsync](https://github.com/crisis-designer/meetsync) 포트폴리오 데모에서 파생된 실사용 버전입니다. 데모 데이터·가상 시계·개발자 패널을 걷어내고, 호스트가 실제 참석자를 직접 추가해 진짜로 쓸 수 있게 만들었습니다. 기획·디자인·개발 문서를 단일 소스(SSoT)로 삼아 AI와 함께 처음부터 끝까지 만든 1인 풀사이클 프로젝트입니다.

---

## 문제 발견과 해결

### Q1. 어떤 문제를 발견했나요?

6명이 회의를 못 잡는 이유를 관찰하면 계산이 어려워서가 아니다 — 27개 슬롯과 6명의 조건을 교차하는 건 산수다. 진짜 문제는 조율 과정에서 사람들이 지불하는 **관계 비용**이다.

주최자는 미응답자를 재촉하는 게 미안하고, 누군가의 비선호 시간으로 확정하는 순간 "왜 하필 그 시간이냐"는 원망의 수신인이 되며, 확정 후 한 명이 빠지면 이 모든 대화를 처음부터 반복해야 한다. 참석자는 "가능"이라 답하면 그 시간에 박제될까 봐 보수적으로 답하고, "되긴 되는데 점심 직후는 좀…" 같은 진심은 단톡방에서 말하면 까다로운 사람이 되니까 삼킨다. 그래서 결국 목소리 큰 사람의 조건이 이기고, "저는 아무 때나 괜찮아요"라고 말한 사람이 손해 본다.

기존 도구들은 계산(투표, 가능/불가 취합)만 도울 뿐, 사람들이 실제로 괴로워하는 이 비용은 전혀 다루지 않는다 — 이것이 도구가 있는데도 여전히 단톡방에서 일정을 잡는 이유다.

### Q2. 어떻게 해결했나요?

관계 비용을 항목별로 시스템에 이관했다.

- **눈치의 비용** → "가능하지만 피하고 싶다"(비선호)를 시스템에만 말하게 해서 진심의 사회적 비용을 0으로 만들었고, 물리적으로 무리한 시간은 이동 버퍼가 본인 대신 거절한다.
- **재촉의 비용** → 마감 도달 시 시스템이 미응답자를 특정하고 독촉을 대행한다.
- **결정 책임의 비용** → 추천마다 산출 근거(전원 가능/비선호 포함/부분 성립)와 양보하는 사람의 실명을 표기해, 주최자에게 "조건상 이것이 최선"이라는 방어 가능한 근거와 사전에 양해를 구할 대상을 쥐여준다. 집계 히트맵으로 주최자가 동료들의 상황 자체를 이해할 수 있게 했다.
- **번복의 비용** → 확정 직전의 변동(동시성 검증)과 확정 후 이탈(재조율)을 정식 플로우로 설계해, 이탈이 생겨도 이미 모은 5명의 응답은 죽지 않는다.
- 그리고 이 모든 것에 참여시키는 **마찰**을 없애기 위해, 참석자는 가입 없이 링크만으로 응답한다.

### Q3. 왜 이 방식으로 설계했나요?

조율 도구의 실패는 해피 패스가 아니라 엣지에서 온다 — 전원 가능한 시간이 없을 때, 한 명이 응답하지 않을 때, 확정 후 일정이 깨질 때. 그 순간마다 도구가 침묵하면 사람들은 단톡방으로 돌아가고, 관계 비용은 고스란히 부활한다.

그래서 예외 다섯 가지를 부록이 아닌 1급 설계 대상으로 삼았고, 특히 "결과 없음"이라는 상태는 3단계 완화(참조자 제외 → 비선호 격상 → 부분 성립)로 구조적으로 제거했다 — 시스템은 어떤 데이터 조합에서도 반드시 답과 그 근거를 내놓는다. 근거를 항상 실명과 함께 노출하는 건, 자동화의 목적이 결정의 대행이 아니라 **결정의 책임을 사람에게서 덜어내는 것**이기 때문이다.

## 실행 방법

Node.js만 설치돼 있으면 됩니다.

```bash
git clone https://github.com/crisis-designer/meetsync-app.git
cd meetsync-app
npm install
npm run dev
```

터미널에 뜨는 `Local: http://localhost:5173/` 같은 주소를 브라우저에서 열면 됩니다. 로그인·가입 없이 바로 회의를 만들 수 있습니다.

> **알려진 제약**: 데이터가 브라우저 `localStorage`에만 저장됩니다. 같은 브라우저의 여러 탭끼리는 실시간 동기화되지만, 참석자가 다른 기기·브라우저에서 초대 링크를 열면 서로의 응답이 보이지 않습니다 — 진짜 다중 사용자 동기화는 별도 백엔드가 필요합니다.

## 워크플로우 — 문서를 SSoT로 삼아 AI와 빌드하기

Figma 없이 마크다운 문서 4종 + React 컴포넌트(`src/App.jsx`)만으로 제품을 빌드했습니다. 규칙은 단순합니다: **기획·디자인·개발 스펙 간 정합성이 코드보다 우선**합니다.

1. 기능 수정이 필요하면 코드를 먼저 건드리지 않고, 해당 영역의 `[PRD-*]` 태그를 확인한 뒤 `01_master_prd.md`의 해당 구역을 먼저 수정합니다.
2. 문서가 확정된 뒤에만 코드를 수정하며, 수정한 코드 블록 최상단에는 반드시 문서와 동일한 태그 주석을 남깁니다 (`// [PRD-EX-01] ...`).
3. 디자인 토큰(색상 · 곡률)은 `src/App.jsx` 상단의 토큰 변수 정의부와 `02_design_system.md` 명세만 수정하면 전체 UI에 즉시 반영되도록 격리했습니다.

이 방식 덕분에 문서와 코드가 서로의 근거가 되고, 태그를 기준으로 양방향 추적이 가능합니다.

## 기술 스택 & 구현 방식

- **React 19 + Vite 8** — 표준 Vite 프로젝트 구조(`src/App.jsx`)이며 별도 설정 없이 `npm install && npm run dev`로 바로 실행됩니다.
- **Tailwind CSS (Play CDN)** — 앱이 뜰 때 `App.jsx`가 Tailwind CDN 스크립트와 커스텀 색상 토큰(`tailwind.config`), Geist 폰트를 스스로 부트스트랩합니다. 별도 빌드 파이프라인 없이도 어떤 환경에 옮겨도 동일한 디자인 시스템이 그대로 구동되게 하기 위한 선택입니다.
- **서버 없음** — 그리드 편집, 추천 연산, 마감 판정, 히트맵 집계까지 전부 브라우저에서 실제로 동작합니다. 데이터는 `localStorage`로 영속화되며, 마감 판정은 실제 시각(`Date`) 기준입니다.

## 테스트

핵심 추천 연산·게이팅 로직은 순수 함수로 분리해 Node 환경에서 회귀 테스트합니다. `harness/app_test.jsx`는 이 로직들을 검증용으로 담아둔 독립 스냅샷이며, `src/App.jsx`와 100% 동기화된 상태는 아닙니다 — 알고리즘 자체(추천 연산 3단계 완화, 재조율 게이팅 등)의 회귀를 잡는 용도로 참고해주세요.

```bash
cd harness
npm install react --no-save
npx esbuild app_test.jsx --bundle --platform=node --format=cjs --outfile=app_test.cjs
node run_tests.cjs
```

`calculateBestTime`(추천 연산 3단계 완화), `deriveRematchGate`(재조율 게이팅), `checkDeadlineStatus`(마감 판정), `buildMemberResponse`(응답 데이터 생성) 등 14개 케이스를 검증합니다.
